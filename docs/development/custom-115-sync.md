# 个人 115 上游手动同步

前后端 `Sync Personal 115 Upstream` 均仅通过 Actions 中的 Run workflow 手动触发。后端检查官方 `OpenListTeam/OpenList/main`，并读取个人前端 `custom/115` 最新提交；前端检查官方 `OpenListTeam/OpenList-Frontend/main`。这两个工作流及前端翻译同步的定时配置均已移除。

需要同步时先运行前端工作流，完成候选验证及需要的兼容性审查，再运行后端工作流，更新固定前端版本并验证、发布配套镜像。

## 同步和交付

1. 根据 `build-config/custom-115-sync.json` 中的上游完整 SHA 比较更新，检查上游历史仍包含已接受的基线。
2. 在 `codex/sync-upstream/` 下创建独立候选分支和指向个人 `custom/115` 的 PR。相同输入产生同一候选提交，重跑不需要强制推送。
3. 使用当前个人分支上的可信工作流定义，验证候选提交。后端执行测试、115 竞态检查、固定前端构建、amd64/arm64 镜像构建和隔离启动检查；前端执行同步脚本测试、类型检查、单元测试和固定语言包构建。
4. 路径规则允许自动合并且验证成功时，普通快进推送候选提交到 `custom/115`，核对远端 SHA。分支在验证期间变化时停止，保留 PR。
5. 后端复用同一次运行中已经验证的镜像 artifact，发布 GHCR 多架构镜像。发布开始及更新滚动标签前再次检查源码 SHA 仍为个人分支 HEAD。

没有更新时不创建 PR 或构建镜像。普通同步只修改用户个人仓库，不向官方仓库创建 PR。

## 兼容性审查

手动触发后，自动合并使用明确的路径允许列表。后端允许普通说明、翻译及独立驱动更新；115 驱动、共享内部代码、服务端、依赖、构建和工作流改动需要审查。未列入允许列表的路径以及任何删除也需要审查；重命名按删除和新增分别检查。规则不根据提交消息是否提到 `115` 或 `info_hash` 判断影响。

需要审查的更新仍自动准备 PR、执行能够执行的验证并记录结果，但不会自动合并或发布。审查共享任务变更时确认：

- 原始 `info_hash`、存储和账号绑定可以保存、恢复及查询。
- 已受理任务恢复或重试时继续查询原云任务；未知受理结果不得自动重新提交。
- 默认本地删除先保存删除标记；失败保留任务。云清理默认保留下载文件，只有明确勾选“是否删除源文件”时才删除对应文件，并独立核对云记录与文件的删除结果。
- 批量操作的逐项结果、权限和其他工具行为仍符合接口约定。

审查后通过 GitHub 合并 PR，正常推送事件触发个人构建。发生文本冲突时，PR 使用上游提交作为候选，验证跳过，需手工整合个人功能并更新上游 checkpoint。上游引入 `AGENTS.override.md` 或 `docs/115/` 时，脚本在推送候选前停止，先保护本地文件再处理同名路径。

路径分类和 CI 通过不代表业务语义已经全部审查，也不能代替真实账号验收。

## 前后端配套

后端只接受个人前端分支的完整 SHA，并要求该 SHA 有成功的个人前端推送构建，或可信同步流程写入的 `custom-115/frontend-validation` 成功状态。失败或尚在构建的最新提交不更新已有 pin。前端历史不能倒退或脱离已有 pin。

验证后的新版本写入 `build-config/custom-115-frontend.conf`，随候选提交一起接受和构建；前端只更新时也会产生后端候选。后端读取公开前端仓库，不需要跨仓库写权限或额外 PAT/GitHub App。

## GitHub 首次配置

- 两个个人仓库的默认分支设为 `custom/115`，让网页手动入口使用个人工作流；`main` 保留作上游对照。
- 在两个仓库的 Actions 设置中允许 GitHub Actions 创建 PR。工作流为准备和接受任务分别声明最小写权限，验证任务不保留 Git 推送凭据。
- 启用两个 `Sync Personal 115 Upstream` 工作流以保留手动入口。个人前端继承的 `Sync i18n files` 工作流保持停用，翻译继续通过个人构建的固定语言包处理。
- 同步使用仓库自动提供的 `GITHUB_TOKEN`。该令牌的推送不会触发后续 `push` 工作流，因此候选验证使用 `workflow_call`，自动接受后的后端发布直接复用当前运行的 artifact。

镜像发布不负责重建设备上的容器。

## 手动执行和排查

在个人仓库 Actions 中选择 `Sync Personal 115 Upstream`，点击 Run workflow，选择 `custom/115`。查看运行摘要、同步 PR 及候选提交的状态；验证失败或目标分支变化后重新运行。需要审查的 PR 完成处理前，不修改路径规则来绕过该次审查。

只读检查在干净的个人分支 checkout 执行，结果放在仓库外或本地忽略目录：

```sh
python3 -B scripts/sync_custom_115.py prepare --dry-run --result /tmp/openlist-sync-inspection.json
```

脚本测试使用临时 Git 仓库和模拟 GitHub API，不访问真实账户或写入 GitHub：

```sh
python3 -B -m unittest discover -s tests -p 'test_sync_custom_115.py' -v
```
